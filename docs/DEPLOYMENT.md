## 1. خريطة النشر

| البيئة | المنصة | قاعدة البيانات | متى تُستخدم |
|---|---|---|---|
| **سحابية** | Vercel (نشر تلقائي من `main`) | SQLite مؤقت لكل نشر معاينة + خدمة قاعدة سحابية متوافقة عند الإنتاج (Turso/libSQL أو Vercel Postgres عند اعتماد صاحب المشروع) | العرض، التطوير، تجربة الوظائف |

## 2. Vercel — الإعداد (مرة واحدة)

1. ادخل [vercel.com](https://vercel.com) → **Add New Project** → استورد `tarikchouika/F-W-M-S` من GitHub.
2. إعدادات البناء تُكتشف تلقائيًا (Next.js). لا حاجة لتخصيص.
3. أضف **Environment Variables** (Production + Preview):
   - `DATABASE_URL` — قاعدة البيانات السحابية (أو `file:./db/preview.db` للمعاينة).
   - `AUTH_SECRET` — سر جلسات JWT (توليد: `openssl rand -base64 48`).
   - `NEXTAUTH_URL` — نطاق النشر.
4. Deploy. كل push إلى `main` = نشر تلقائي. كل PR = رابط معاينة.
5. أضف نطاق Cloudflare إلى المشروع (Step 3) واتبع تعليمات DNS.

## 3. Cloudflare — الإعداد

**معرّف الحساب:** `758fcc827f3338772847c28391b6c6c3` — **رمز الـ API يُحفظ في `.env`/أسرار المنصات فقط ولا يُكتب في أي ملف مرفوع.**

### 3.1 DNS للنطاق السحابي (Vercel)
في لوحة Cloudflare → DNS → سجلات تشير إلى نطاق Vercel (`cname.vercel-dns.com`) حسب تعليمات Vercel عند إضافة النطاق. وضع الوكيل (Proxy) اختياري.

### 3.2 Tunnel للخادم المحلي (الهاتف)

```bash
# على الهاتف (Termux/Ubuntu) — بتنسيق cloudflared:
cloudflared tunnel login
cloudflared tunnel create fwms-local
cloudflared tunnel route dns fwms-local fwms-local.<نطاقك>
cloudflared tunnel run --url http://localhost:3000 fwms-local
```

- ملف الإعداد المرجعي: `infra/cloudflare/tunnel.example.yml` (بلا أسرار).
- الخادم المحلي يصبح متاحًا عبر `https://fwms-local.<نطاقك>` بلا فتح أي منفذ.
- **التحقق الجغرافي للحضور يبقى إلزاميًا في الوضعين** على الخادم نفسه (SPEC §4.2) — النفق مجرد نقل، لا يغيّر قواعد التحقق.

## 4. سياسة الأسرار (نافذة)

| السر | أين يُخزَّن | ممنوع |
|---|---|---|
| GitHub PAT | مدير اعتمادات git المحلي فقط (أو GitHub CLI) | ❌ في أي ملف مرفوع |
| Cloudflare API Token | `.env` على الجهاز المخوَّل + أسرار Vercel عند الحاجة | ❌ في الكود/التوثيق |
| Vercel Token | أسرار GitHub Actions عند أتمتة النشر | ❌ في الكود |
| `AUTH_SECRET` | `.env` / متغيرات Vercel | ❌ في الكود |
| روابط قاعدة الإنتاج | متغيرات المنصة | ❌ في التوثيق |

**عند اشتباه تسريب:** إبطال فوري من لوحة الجهة → تنظيف تاريخ Git إن لزم → تدوير كل الأسرار → إبلاغ في `docs/WORKLOG.md`.

**الدفع من بيئة بلا مدير اعتمادات** (بيئة التطوير السحابية أو Termux):
```bash
FWMS_GITHUB_TOKEN=ghp_xxxxxxxxxxxx ./scripts/push.sh   # يدفع main + الوسوم
```
التوكن كمتغير بيئة فقط — يُبطل فور انتهاء الحاجة، ولا يُخزَّن في أي ملف.

## 6. الانتقال بين البيئتين (SPEC §7)

- **محلي → سحابي:** نسخة احتياطية SQLite → استيراد إلى القاعدة السحابية → فحص تطابق عدد السجلات لكل جدول → توثيق في WORKLOG.
- **سحابي → محلي:** العكس بنفس الخطوات.
- الأداة المرجعية: سكربت `infra/termux/backup.sh` (المساعد الثاني) + فحص `sqlite3 .schema` مقابل `prisma migrate status`.
